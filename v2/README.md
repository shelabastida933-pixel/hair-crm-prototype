# 发丝管家 v2（多角色版）

## 与 v1 的区别

| | v1（`app/`） | v2（`v2/`） |
|---|---|---|
| 定位 | 单店个人工具 | 多角色预约系统 |
| 用户 | 只有老板娘 | 顾客 / 员工 / 店长 |
| 预约 | ❌ | ✅ 30分钟粒度 + 容量校验 |
| 排班 | ❌ | ✅ 员工自设工作时间 |
| 服务能力 | ❌ | ✅ 床位 ∩ 在岗员工 |
| 数据 | 本机 IndexedDB | 本地模式 / 云端模式可切换 |

**v1 原样保留，线上照常可用。**

## 功能

### 顾客端
- 填姓名+手机号即登录（无需密码）
- 选服务 → 选日期 → 选时段
- 只在「有人能服务」的时段可选
- 查看/取消自己的预约

### 员工端
- 账号密码登录
- 设置自己每周哪几天上班、每天几个时间段
- 最小 30 分钟粒度，可设多段（如 9-12 / 13:30-18）
- 查看今天自己的预约

### 店长端
- 今日预约看板 + 待分配提醒
- 代客预约（客户打电话来帮约）
- 给预约分配/改派技师
- 店铺设置：床位数、联系电话、**是否允许客户指定技师（默认关闭）**
- 员工与工作时间一览

## 核心算法

```
可约容量 = min(会做该项目的在岗员工数, 床位数)
剩余 = 容量 - 已约数

一条预约 = 锁连续 N 个 30 分钟格子（N = 服务时长/30）
指定技师时：该技师每个格子都要「在岗 + 空闲 + 会做」
全程必须落在营业时间内
```

## 数据模式

`js/db.js` 顶部：

```js
const API_CONFIG = {
  mode: 'local',      // local = 浏览器本地；cloud = 接后端
  baseUrl: '',        // cloud 模式下填后端地址
};
```

**当前是 local 模式**：数据存在各自浏览器里，用来演示和验证流程。
要真正多端共享（顾客预约后店长能看到），需要把 `mode` 改成 `cloud` 并部署后端。

## 已知限制

1. **local 模式下数据不共享** —— 不同浏览器的数据是隔离的，只适合演示
2. 没有消费/储值模块（下一期）
3. 没有总部多店管理（下一期）

## 总部运营中心（`hq/`）

**独立网址**：`/v2/hq/index.html`

### 定位

| | 店长后台 | 总部后台 |
|---|---|---|
| 看什么 | 本店今天该干什么 | **所有店谁在变差** |
| 时间 | 今天、这周 | 月、环比 |
| 形态 | 手机 H5 | **PC 网页** |
| 核心 | 行动 | **判断** |

### 五个 KPI
门店数 / 总营收（含环比）/ 预约→到店 / 整体到店率 / 平均客单价

### 四个对比维度（每店）

1. **业绩**：营收、环比、客单价
2. **客流**：预约数、到店率
3. **客户**：新客数、复购率、卡内余额沉淀
4. **人效**：工时利用率

### 异动预警（核心价值）

不是给数字，是告诉人"哪里出了问题 + 怎么处理"：

```
📉 营收连续 3 个月下滑
🚪 到店率明显偏低
💳 卡内有钱但客户不来（最值钱的挽回名单）
👥 技师工时利用率低（空转成本）
🔄 复购率过低
```

每条预警都带**建议动作**。

### 演示数据说明

`hq/data.js` 是**假数据**（5 家店），刻意做出"1 家好、1 家差"的对比。
真实接入时，把 `hqShopMetrics()` 的数据源换成云端聚合查询即可，指标口径不变。

### 当前限制

1. **数据是假的** —— 用于展示形态，不是真实经营数据
2. **没有下钻** —— 点不进去看具体客户/预约（真实版需要）
3. **没有任务派发** —— 预警只能看，不能派给店长处理（真实版需要）
4. **没有账号体系** —— 独立网址已规划，登录逻辑待接
